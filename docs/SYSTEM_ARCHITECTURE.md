# Master Architecture Definition

This document satisfies **Phase 2 — Architecture**, defining the exact technical blueprints across 12 specific domains for the Legalnorms Consultations platform.

## 1. System Architecture
**Modular Monolith (Stage 1).** The entire application operates as a unified Next.js deployment containing both the API and UI. Strict internal boundaries separate domains (`src/features` vs `src/services`). This architecture avoids the latency and complexity of microservices while retaining the ability to extract heavy workloads (e.g., Ingestion Pipelines) in the future when scaling mandates it.

## 2. Frontend Architecture
**React Server Components (RSC) + Tailwind v4 + Progressive Disclosure.** 
- The UI defaults to Server Components to ship zero JavaScript for massive regulatory tables and text.
- Client Components (`"use client"`) are heavily restricted to interactive nodes (Search inputs, Modal Dialogs).
- All complex data uses the `ProgressiveDisclosure` pattern to manage cognitive load. 
- Mobile devices automatically receive degraded Card-stack views instead of raw data tables (`ResponsiveDataList`).

## 3. Backend Architecture
**Next.js Server Actions + Node.js Edge API.**
- Backend boundaries are strictly divided: Route Handlers (`src/app/api`) handle external B2B traffic. Server Actions handle internal dashboard form mutations.
- Both routes immediately delegate to a pure Node.js **Service Layer** (`src/services/`). The service layer executes business logic and hands off to the **Repository Layer** (`src/repositories/`).
- Zod parses every incoming payload.

## 4. Database Architecture
**PostgreSQL + Drizzle ORM.**
- A highly normalized relational schema.
- Data integrity is enforced via physical foreign keys (`.references()`) and composite unique indexes (e.g., blocking duplicate drug records).
- All entity tables include `created_at` and `updated_at`.
- Strict prohibition on hard deletes for historical regulatory intelligence.

## 5. Storage Architecture
**Object Storage (S3-Compatible API).**
- All regulatory PDFs, XML dumps, and medical image assets are stored immutably in a bucket.
- The PostgreSQL `regulatory_documents` table stores only the metadata (`objectKey`, `bucketName`, `mimeType`) and a reference to the S3 object.
- Access to private portfolio documents is gated via signed URLs generated by the Node backend.

## 6. Caching Architecture
**Multi-Tiered (CDN + Redis).**
- **Tier 1:** Vercel/Cloudflare CDN caches all static assets and public SEO routes (`/drugs/[slug]`).
- **Tier 2:** Redis handles ephemeral application state, rate limiting, and API key token rotation.
- **Tier 3:** Next.js Data Cache handles query memoization during the RSC render cycle.

## 7. Search Architecture
**PostgreSQL FTS -> Dedicated Search Engine.**
- Initial rollout utilizes Postgres Full-Text Search (`to_tsvector`) for drug/manufacturer lookups.
- Stage 2 Migration involves a CDC (Change Data Capture) pipeline syncing Postgres to Algolia or ElasticSearch for sub-50ms typo-tolerant search across millions of regulatory PDFs.

## 8. Authentication Architecture
**Supabase Auth + Bearer Tokens.**
- Dashboard Users: Authenticated via OAuth/Email leveraging secure HttpOnly cookies, completely invisible to client JavaScript.
- API Consumers: Authenticated via long-lived Bearer API Keys validated via Redis middleware (`ApiSecurity`), heavily rate-limited by subscription tier.

## 9. Authorization Architecture
**Multi-Tenant Role-Based Access Control (RBAC).**
- Users belong to `organizations`. All sensitive queries automatically append `WHERE organization_id = ?`.
- Granular permissions (e.g., `drugs:write`, `org:invite`) are enforced dynamically at the Service Layer.
- Dangerous UI actions require manual type-to-confirm validation (`CriticalActionDialog`).

## 10. Background-Job Architecture
**Asynchronous Queue Workers.**
- The UI must never block while waiting for a 100MB FDA XML file to parse. 
- The `NotificationService` and Ingestion Pipelines push payloads onto a Redis-backed queue (e.g., BullMQ).
- Dedicated worker processes consume these queues, execute the heavy compute, and emit database updates or send emails.

## 11. Observability Architecture
**Structured JSON Logging + Distributed Tracing.**
- `console.log` is strictly banned in production.
- A centralized `Logger` class emits NDJSON (Newline Delimited JSON) containing `requestId`, `userId`, `latencyMs`, and the `event`.
- Data flows into Datadog/Sentry for metric tracking, alerting on 500s, and API abuse detection.

## 12. Deployment Architecture
**Immutable Containerization / Serverless.**
- Driven entirely by CI/CD (`.github/workflows/ci.yml`). Code is linted, type-checked, tested, and built.
- Infrastructure configurations (Environment variables) are validated at boot time via Zod (`src/config/env.ts`).
- Missing secrets result in a hard crash, preventing the app from serving traffic in a compromised/degraded state.
